# 崽崽小看板 · MVP 需求文档

> 版本 0.1（2026-10-09）。替代原计划引用的 `niuniu-care-mvp_0_8cpf.md`（该文件未入库，本文件根据 `reference/mvp-dev-plan.md` 与已确认决策重写）。
> **第 11 节验收清单是最终裁判。**

## 1. 一句话

家长在 Web 上配置宝宝的照护事项（支持一句话 / AI 解析排期），奶奶在 Android App 上看今天要做什么、做了就点确认，全家看到同一份记录，不用再在微信里问"今天 AD 吃了没"。

## 2. 名称与可定制

- 产品名：**崽崽小看板**（App 名、Web 标题固定）。
- **宝宝昵称可自定义**：每个部署自己设置（如"牛牛""豆豆"），默认"崽崽"。界面文案用昵称拼出，例如"牛牛今天的事""牛牛的 AD 已喂"。
- 为后续开源做准备：代码里不出现任何具体家庭的名字、邮箱、地址；所有家庭相关配置走数据库设置或部署变量。
- 一个部署 = 一个家庭 = 一个宝宝（多孩子明确不做，见第 10 节）。

## 3. 角色

| 角色 | 端 | 能做什么 |
| --- | --- | --- |
| 家长（爸爸/妈妈） | Web（手机浏览器优先） | 建/改/暂停/归档事项；登记、跳过；看历史；设置昵称与家庭成员显示名 |
| 照护人（奶奶） | Android App + 桌面小组件 | 看今日/明日；点确认登记（也可只看不点）；2 分钟内撤销自己的登记 |

记录人：Web 由 Cloudflare Access 登录邮箱映射显示名；App 在首次设置时选择"我是谁"。

## 4. 核心概念

- **事项（task）**：一件重复要做的事，如"AD 一粒""钙 1 袋"。有名称、类型（补充剂；用药为后续）、排期、优先级、状态（进行中/暂停/归档）、备注。
- **排期（schedule）**：每天 / 每隔 N 天；每次有一个或多个时间点；可选结束日期（P2）；一周几次（P2）。
- **实例**：某事项在某业务日某时间点的一次"该做"。由服务端按排期实时算，不预先生成。
- **登记（completion）**：对一个实例的结果：已做 / 跳过（带原因）。同一实例只有一条有效登记。
- **业务日期**：按 Asia/Shanghai 时区的自然日。

## 5. 功能需求

### 5.1 今日看板（Web + App）
- F1 显示今天的全部实例：未登记在前，按时间排序；已登记的显示"谁、几点"。
- F2 每个未登记实例有主按钮"确认已喂"；次要操作"跳过"（需选/填原因）。
- F3 显示明天的实例，只读。
- F4 状态不只靠颜色：图标 + 文字（"待喂 / 已喂 / 已跳过"）。
- F5 页头显示"{昵称}今天的事"、日期、星期、未登记数。

### 5.2 新建/编辑事项（Web）
- F6 一句话输入（文字或 🎤 语音），解析成排期；显示人话描述 + 未来 7 天预览 + 黄色提醒（没说清的地方）。
- F7 解析结果**必须用户确认后才保存**；解析失败或不准时，可直接手动填表单。
- F8 P1 规则解析至少支持："AD 隔天吃 早上8点""钙每天晚上7点"。P2 接 Gemini，支持"感冒药一天三次，吃3天"。
- F9 可改名称、排期、备注；暂停/恢复/归档。暂停或归档的事项不出现在看板。

### 5.3 记录（Web）
- F10 最近 14 天按日分组：每个实例的结果、记录人、时间；漏登记的显示"未登记"。

### 5.4 设置（Web）
- F11 宝宝昵称；家长邮箱 → 显示名映射；照护人显示名列表（供 App 选择）。

### 5.5 Android 奶奶端
- F12 打开即今日看板，不需要找菜单。大字（正文 ≥20sp）、触控区 ≥48dp。
- F13 登记后 2 分钟内显示"撤销"，只能撤销自己的记录。
- F14 打开时语音播报（系统 TTS，可在设置关闭）：最多播 3 项未登记事项。
- F15 离线可看最近一次同步的看板，明确显示"离线 · 最后同步 HH:mm"，不假装是最新；离线登记先存本机，联网后自动补传。
- F16 桌面小组件：日期、未登记数、前 3 项、最后同步时间；点击进入 App。
- F17 提醒通知为"尽力而为"，不承诺精确到分钟。
- F18 首次设置：服务器地址、家庭口令、我是谁、播报开关。

## 6. 数据与一致性

- 服务端（D1）是唯一真相；App 只是缓存。
- 登记幂等：同一事项、同一业务日、同一时间点重复提交只算一条。
- 撤销为软删，保留审计。
- 改排期只影响今天未登记的实例和以后，不改写已有登记。

## 7. 安全与隐私

- Web 整站在 Cloudflare Access 后面，仅家庭成员邮箱可进。
- App 用家庭口令（FAMILY_KEY）调用 API；口令存在 App 私有存储。
- **任何第三方 API Key（Gemini）只存在 Worker Secrets**，Web 和 App 都不持有。
- 仓库不含任何真实口令、邮箱、database_id 以外的家庭信息。

## 8. AI 解析边界

- AI 只做"翻译"：一句话 → 结构化排期；不做医疗建议、不推荐剂量。
- 模型：Gemini `gemini-3.8-flash`（可通过部署变量更换）；失败、超时、无 Key 时降级规则解析，不阻塞建事项。
- 用药相关输入在 warnings 里提示"请按医嘱核对剂量与疗程"。

## 9. 非功能

- Web 手机优先，375px 宽可用；首屏 2 秒内可操作（4G）。
- App 最低 Android 7.0（minSdk 24）；冷启动到看板可见 ≤2 秒（有缓存时）。
- 时区固定 Asia/Shanghai；跨零点后看板自动切到新的一天。

## 10. 不做（MVP）

精确闹钟、农历排期、多孩子、公开注册、账号体系、医疗建议、旧版"家小满"补给功能（已整体移除）。
后续 backlog：疗程与症状记录、疫苗/体检提醒、过敏忌口、生长曲线、喂养/睡眠/排便、外出交接、库存联动。

## 11. 验收清单（最终裁判）

**数据与排期**
- [ ] A1 建"AD 隔天 8:00"，连续 3 个业务日看板依次为 有/无/有；跨月份依然正确。
- [ ] A2 建"钙每天 19:00"，每天出现一次。
- [ ] A3 同一实例 Web 和 App 几乎同时点确认，历史里只有一条记录。
- [ ] A4 暂停的事项当天起不出现；恢复后按原锚点继续隔天。
- [ ] A5 23:59 与 00:01（北京时间）看板分属两天，不受手机/服务器时区影响。

**Web（家长）**
- [ ] B1 手机浏览器打开需 Access 登录；未授权邮箱进不去。
- [ ] B2 一句话"AD隔天吃早上8点"解析出正确排期和 7 天预览，确认后保存。
- [ ] B3 解析失败时可手动填表建事项。
- [ ] B4 （P2）"感冒药一天三次，吃3天"→ 每天 3 次 + 结束日期 + 黄色提醒。
- [ ] B5 14 天历史显示记录人和时间，漏登记可见。
- [ ] B6 改昵称后，Web 与 App 文案都随之变化。

**App（奶奶）**
- [ ] C1 打开 App 第一屏就是今日看板，不用点任何菜单。
- [ ] C2 字够大、按钮够大，奶奶能独立完成一次确认。
- [ ] C3 不点任何东西也能看清今天还剩几件、各是什么。
- [ ] C4 登记后 2 分钟内可撤销，超时撤销按钮消失；不能撤销别人的记录。
- [ ] C5 关掉网络：显示"离线 · 最后同步 HH:mm"；离线点确认，联网后自动同步且不重复。
- [ ] C6 打开时播报最多 3 项；设置中关闭后不播。
- [ ] C7 小组件显示日期、未登记数、前 3 项、最后同步时间，点击进 App。

**安全**
- [ ] D1 无口令调用 `/api/*` 返回 401；错误口令 401；正确口令 200。
- [ ] D2 App 安装包和 Web 前端代码中搜不到 Gemini Key。

**试用（P4）**
- [ ] E1 连续 7 天真实使用 AD/钙，无日期错位、无重复登记。
- [ ] E2 家里认为"比在微信里问更省心"。
